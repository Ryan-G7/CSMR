# AMG GT 大厅 MR 整车评审

实际 Unity 工程在本目录 `CarAR`，使用 Unity 6000.6.3f1。部署链路为 Windows / Pimax OpenXR / 荟镜 HJXR 透视。系统审查与尚缺少的正式评审能力见 [代码审查报告](CODE-REVIEW.md)。

首次克隆、免编辑器运行包下载和可移植构建命令见 [仓库首页](../README.md)。MRTK 依赖随仓库位于 `../Vendor/MRTK`，无需子模块；原始模型使用 Git LFS。

## VR 室内展厅

`CarVR.unity` 使用 `D:\BaiduNetdiskDownload\CarRoom-2.blend`。`Launch.unity` 在创建 XR rig 之前按启动参数选择模式：无参数为原桌面预览，`--hjxr` 为原荟镜 MR，`--vr` 为原生 OpenXR VR，`--vr-desktop` 为桌面第一人称漫游，`--vr-smoke` 为 VR 自动回归。根目录有两个 VR 启动器，完整操作见仓库首页。

VR 在 OpenXR 输入启动后重新请求 Floor 参考空间，等待定位稳定再放置访客。若眼高低于 0.25 米或高于 2.7 米（例如旧定位把视点放到地下约 15.6 米），改用 Device / LOCAL，并通过相机与手柄共用的父节点恢复 1.65 米初始眼高，之后保留真实蹲下与头部移动。`[CarAR VR Origin]` 日志记录实际参考空间、原始位置、眼高和偏移；无法恢复有效定位时显示错误，可按 F2 进入桌面漫游。

静态场景导出为 `Assets/Environment/VR/CarRoom.glb`，源文件、哈希、车辆摆放和色彩配置记录在 `carroom.json`。对应发动机盖顶点拟合车辆刚体摆放，误差小于 0.002 米；原静态车被排除，替换为已有的可交互 AMG。保留全部岩壁面，按 2 米空间单元及顶点上限拆块；保留源 UV、最高 4K 贴图，复杂颜色 / 粗糙度 / 法线由 Cycles 求值。导航来自实际环境几何；内饰观察允许贴车及穿过车身，车辆不再整块挖空导航，也不再把访客的角色胶囊顶到车顶。房间墙壁和地面边界保持约束，传送落点检查环境胶囊空间与路径连通性，车顶不是可达地面。缓存复用时也重新生成导航，保留现有光照烘焙。

VR 使用独立 HDR URP 和 4x MSAA，关闭 VR 的屏幕空间遮蔽以避免车门边缘及内饰黑色伪影。Unity 以 24 texels/m 分配最终 UV2 图集，Blender Cycles 使用原材质与 world，在最终 UV2 布局上以八倍边长烘焙带材质颜色的直接光及间接光（256 samples，linear EXR）；当前为 4096² 和 2048² 两张图集。这保留原节点的几何遮蔽与颜色细节，运行时不再重复乘一次底色。原灯带的发光强度参与烘焙。另渲染 2048×1024 的室内 HDR 全景，生成粗糙度卷积反射和室内漫反射球谐，供可开合、可爆炸的车辆使用；车辆不烘焙进固定光照图；地面材质叠加固定的闭合整车轮廓阴影；运行时独立复制投影用的网格节点并复用模型资源，车门开关与爆炸零件不会改变该轮廓。车辆可见材质不接收实时阴影，各零件也不单独投影。阴影方向按源顶灯发光三角面的面积与亮度加权，使用单主方向近似面光源遮挡；这不是 Cycles 的逐盏面光追踪，保留烘焙环境光与间接补光，不重复照亮房间。岩壁与墙顶使用烘焙的漫反射，避免室外开口在房间中央反射探针中造成错误的墙面高光；木地板与金属保留实时镜面反射，灯具以 HDR 发光表面显示。源 HDR 保留 Mapping 旋转。Blender 生成包含源曝光、Filmic 与 Medium High Contrast 的 3D LUT，由双眼兼容的 Render Graph pass 应用；当前额外曝光修正为 0 EV。精细 / 流畅分别使用 100% / 80% 渲染比例。

`Tools/Export-VRScene.ps1 -SourcePath <scene.blend> -Reference` 只读源文件，使用临时副本导出并生成参考图，不覆盖 Blender 源。导出后运行 `Tools/Bake-VRLighting.ps1`，自动准备 Unity 最终几何和 UV2、烘焙 Cycles 光照、渲染室内 HDR。再运行 `Tools/Build-Windows.ps1 -Smoke` 构建。构建检查源 / GLB 哈希和 UV2 布局，拒绝过期光照；源文件在本机可用时同时验证源哈希。未安装 Blender 的机器可使用已导出的模型、场景与烘焙资产直接构建。

`Build-Windows.ps1 -Smoke` 验证原 MR 四组回归及 VR 导航、非法落点、场景固定、门盖、爆炸 / 还原、画质和原生 XR 输入事件回放。检查摇杆回中、单次 30° 转向、以头部为轴旋转、恢复跟踪防误触及掉线取消传送。阴影回归检查地面投影仍然可见，以及切换整车投影不会使驾驶位内饰变暗。自动检查不能代替头显双眼成像、舒适度与实际性能的佩戴验收。

VR 每次启动强制使用“精细”画质：100% 渲染比例、4096 阴影贴图，不自动降到流畅。传送前让摇杆回中，再向前推住右摇杆瞄准，打开的面板会自动收起；绿色落点才可达，松回中立区提交。松杆途中的中间数值不会再提前取消瞄准。回归会通过真实 Input System 事件验证完整传送，并比较开关阴影的渲染图。

左摇杆连续移动默认开启，方向相对头部，保留回中和跟踪恢复防误触；主动推杆自动收起面板，传送瞄准期间不同时连续行走。菜单 / Y / B 选择“进入驾驶位”可切到约 1.05 米的坐姿眼高，看方向盘、仪表台和内饰；左摇杆仍可穿行观察。选择“下车 / 恢复站立”、返回入口或其它传送后恢复原眼高。近裁剪改为 0.02 米，减少贴近内饰时的裁切。失跟立即停控，持续 0.15 秒才渐黑，稳定恢复 0.12 秒后重新等待摇杆回中；运行日志会记录跟踪变化。自动回归新增左杆移动、近车落点、驾驶位出入、穿过车门时无视点上顶及短暂失跟不闪黑检查，驾驶位检查图为 `Build/Windows/vr-cabin.png`。

录屏：根目录 `启动VR录屏模式.cmd` 对应 `Launch/Start-VR.ps1 -Recording` 与 `--vr-recording`，独立于普通启动。开启后 URP 渲染比例额外乘 0.65（精细 0.65 / 流畅 0.52），减少约 58% 的每眼像素数，保留精细档 4096 阴影、4x MSAA、模型和材质。普通启动仍为精细 1.0。菜单“录屏优化”或焦点窗口 F8 即时切换；原生 XR 控制显示节奏，不用桌面限帧冒充头显限帧。所有 VR 档位均关闭未被场景材质使用的 opaque color copy，减少双眼高分辨率复制。录屏窗口请求 1920×1080；EV 建议先录窗口区域、1080p / 30 帧。负载改善不等于 EV 抓取黑屏已经排除。回归分别验证普通与录屏启动、按钮切换以及画质组合恢复；日志分别为 `vr-headset.log` / `vr-recording.log`，包含 renderScale 和眼纹理尺寸。

## 当前空间定位方式

2026-10-20 已删除实体定位板工作流，包括绿色参考框、校准按钮、长按 X / K 快捷键、WorldSync 调用、厂商日志结果解析和自定义 OpenXR 输入空间变换。

删除依据是设备日志中校准后相机输入与双眼视图坐标不一致，自定义输入修正次数为 0，随后请求超时。此前调整板尺寸、结果读取与输入适配仍未获得佩戴者的贴合验收。应用现在保留原生头部 / 手柄跟踪，不再用定位板改变参考空间。厂家安装目录的相机标定文件没有在此次修改。

荟镜模式在 OpenXR 输入启动后请求厂家 demo 使用的 Device / LOCAL 参考空间，并将相机附加眼高偏移设为 0。实际结果记录在 `[HJXR Reference]`。车辆是独立世界根对象，停车后不随相机、平面更新或手柄移动；恢复摆放和锁定不代表厂家透视合成已达到现实中的稳定精度。

## 运行与头显操作

双击工作区根目录 `启动汽车MR.cmd`，或运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\CarAR\Launch\Start-HuijingMR.ps1
```

启动脚本自动启动或复用厂家相机后台和 MR 服务器，等待新启动的相机就绪，不重复启动现有 CarAR。缺少真实画面时运行根目录 `修复透视并重启.cmd`，或加 `-RestartCameraBackend`。日志为 `CarAR/huijing-mr.log`，重启前自动备份旧日志。

启动环境变量只传给本次应用，不修改 OpenXR 注册表、不替换厂家 DLL、不调用 SaveConfigToFile。Unity 保留透明 Alpha，VST 在背景、车辆在前景，显式关闭 VR head lock。

1. 完成设备定位和手柄配对，佩戴头显并唤醒至少一只手柄。Windows 首次摆放须等待头显位置 / 旋转有效、已佩戴，且至少一只原生 grip 位姿距头显不超过 3 米，连续稳定 1 秒。随后寻找足够大的水平面；没有平面数据时约 8 秒后放到视线前方约 4.5 米，按 1.5 米眼高估计地面。异常跟踪会重置等待时间。
2. 按菜单键、左 Y 或右 B 呼出面板，选择“选择停放位置”。用手柄射线指向地面，摇杆上下调整整车占地预览的高度。
3. 扳机确认，车辆停放并锁定。菜单 / Y / B 可取消未确认的摆放。
4. 需要细调时解除锁定，在“精细调整”内按 10cm / 5° / 地面 ±1cm 修正，完成后再次停车锁定。
5. 收起面板绕车观察。点选左右门、尾门和发动机盖可开合；门盖和爆炸 / 组装在停车状态下也可操作。

每次确认停放或按 R 重新摆放都会按跟踪空间的竖直方向放平车身，保留车头水平方向与尺寸，并锁定整车操作。占地预览与接触阴影也保持水平；首次隐藏状态下的落地高度按模型局部边界计算，避免使用尚未更新的世界边界。重新摆放保留已有地面支点，不按打开的门盖或爆炸零件重新量高度。

当前运行模型四轮最低点高度差约 0.5mm，本身没有明显倾斜。荟镜当前没有真实地面平面数据，默认 1.5m 眼高只是估计；请用“选择停放位置”的摇杆高度让预览四角贴地。车身放平只保证与跟踪空间的水平面一致，不能校正厂家透视画面或现实地面的角度。若四角仍无法同时贴地，应检查头显运行时地面标定；`[CarAR Floor Pose]` 和放置日志记录地面来源与车身倾角，辅助区分模型姿态与透视/跟踪空间的问题。

面板仅在呼出时定位，随后固定在世界中。使用标准 XRI 射线，aim 无效时回退 grip，恢复后自动切回。解除锁定后可握住车身拖动，双手同时抓取缩放；左摇杆平移，右摇杆旋转 / 缩放。抓取期间摇杆不同时改动车辆。缩放范围为 0.1–10 倍，精细调整、摇杆与双手抓取使用相同上下限；默认仍以 1:1 展示。锁定、尚未摆放或正在爆炸时，相关整车变换被阻止。

Windows 运行中持续检查跟踪。头显失效或已跟踪手柄与头显空间不一致时，锁车并暂时关闭车辆渲染和碰撞，动画对象保持活动。同一坐标空间恢复稳定后恢复原停车位置，手柄休眠不影响已经摆好的车辆。有效位置发生超出合理运动速度的突变时，显示“空间定位已重置，请重新选择停放位置”，必须重新确认停放；预览地面改用当前眼高估计，避免沿用旧坐标的地面。应用不修正原生相机或控制器坐标。

解锁、手柄恢复跟踪或输入重新启用后，必须先松开再按握键才能抓车，摇杆须先回中再操作；拿起已按住握键或推着摇杆的手柄不会自动拖拽或缩放。单手抓取只移动/旋转，不采用射线附着点的缩放。双手距离不足 8cm 或位置非有限值时保持当前比例，恢复有效距离后重新建立基准，避免距离除法让车辆突然缩小或消失。

“切换流畅画质”在原生分辨率 / 4096 阴影 / SSAO 和 80% 分辨率 / 2048 阴影 / 无 SSAO 间切换，均保持 4x MSAA 与 MR 透明背景。窗口失去焦点仍接收 XR 输入；键盘快捷键只在应用有焦点时响应。R 重新摆放，H 呼出面板，M 切换锁定。

## 模型与渲染

当前模型来自 AMG Blender 源文件，仓库保留已导出的模型与材质，默认按源模型米制单位 1:1 展示，未经原厂尺寸标定。重新制作时提供自己的源文件路径，后台导出不覆盖 `.blend`：

```powershell
$env:OIIO_THREADS = "1"
$env:OPENIMAGEIO_THREADS = "1"
& 'D:/Soft/Blender/blender.exe' --background --factory-startup --threads 1 'D:/Sources/AMG.blend' --python-exit-code 1 --python ./Tools/prepare_amg.py
```

导出应用 Mirror / Subdivision，仅沿原有不相连的网格岛分离左右门。门壳、玻璃、门饰件、把手和后视镜使用经过确认的源组件；门内饰、扶手、扬声器与按键按明确来源清单归属左右门，座椅 / 仪表台 / 车身密封框保持固定。上沿长条 `Cube.013` 的两侧网格岛分别随门运动；混合源 `Cube.092` 仅取两侧各 109 顶点的门饰条，中间两块中控台网格保持静态。分岛数量、顶点数及边界有导出断言，来源保留在 JSON。零碎内饰按总成和材质合批，目前为 168 个网格、1,306,154 个三角形。后窗随尾门、发动机盖独立开合，四轮组件整体爆炸 / 组装。源模型缺少门盖内层厚度与完整发动机，双面渲染只能显示现有几何。

外观以 `AMG.blend` 为唯一材质来源。导出器保留 Principled 数值，使用 Cycles 烘焙 glTF 无法表达的颜色、粗糙度和法线输入图；不再替换车漆、轮毂、皮革、地毯、玻璃或灯管的颜色/粗糙度。没有材质的源面显式导出 Blender 默认 Principled 表面，不再套深色装饰材质。

源 Carpaint 是三层 BSDF 混合，不能直接当成单个 glTF 金属清漆材质。`AMG-interactive.json` 记录原始线性颜色、粗糙度、混合权重、Fresnel IOR、烘焙纹理与源文件 SHA-256；Setup/Build 检查源文件哈希，过期导出会明确报错。Unity 的 `BlenderLayeredPaint` 按这些值重建三层。当前底层粗糙度约 0.668、占比约 93.65%，没有额外的清漆权重 1 或金属度 0.9 覆盖。玻璃和发光材质的视角响应从源节点生成 LUT。

默认光照使用项目中的室内摄影棚 `Assets/Environment/brown_photostudio_02_2k.hdr`，强度 1、旋转 0。该 HDR 同时生成带粗糙度卷积 mip 的反射 Cubemap 和漫反射球谐环境光；场景保存同一 HDR 的反射引用与 27 个漫反射系数。已删除虚构大厅、反射灯带和默认强直射灯；补光初始强度为 0，菜单可手动添加。MR 相机仍清为透明，HDR 仅参与照明与反射。桌面预览共用相同光照。纹理使用 16 倍各向异性过滤，无负 mip 偏移。

ARFoundation 请求测光与环境探针，只有提供方实际输出数据时才更新；过期/非法测光恢复 HDR 环境和零补光。当前厂家链路没有已验证的实时环境贴图接口。为保留透视 Alpha，主颜色缓冲关闭 HDR，环境反射纹理保留 HDR。

当前 Windows / Pimax OpenXR / HJXR 实机日志明确报告没有 AR Camera 和 Environment Probe 提供方，因此目前**不能接收现实房间的实时光照**，也不会根据房间开关灯更新 HDR 反射。厂家透视视频由合成层提供，不等于 ARFoundation 测光输入。设置页显示“静态 HDR · 现实测光未接入”；“HDR / 自动光照”在无提供方时恢复静态 HDR。`[CarAR Lighting]` 记录实际提供方、当前功能和是否收到有效样本。

MR / 桌面预览使用摄影棚 HDR，VR 使用展厅源光照；环境内容本身会改变反射。URP 与 Blender 的 BSDF、多次散射、色调映射存在差异，不能宣称逐像素一致。程序化图烘焙在一个 UV 单元内；Object/Generated 坐标纹理在单位平面上求值，不能完全保留每个原始物体的三维程序化分布。实时玻璃不做真实折射，彩色透射近似为标量透明度。

这台 Windows 机器上的 Blender 5.2 在 glTF 导出成功后的原生退出清理中会崩溃。导出器使用临时 `.blend` 副本和一次性导出进程，在文件写入、GLB 头和 JSON 检查后直接退出该进程，父进程继续校验材质、法线、切线并发布结果；失败不会替换模型。原始 `AMG.blend` 不会保存。HDR 漫反射的 27 个球谐系数显式存入场景组件，避免编辑器 RenderSettings 的临时值在播放器中丢失。

## 验证与现实精度边界

